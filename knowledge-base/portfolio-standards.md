# Public Portfolio: Security & Publication Standards

This public GitHub portfolio documents engineering techniques, not customer deliveries. Examples must be independently authored with synthetic data.

## Publish

- Synthetic fixtures, schemas, and domain-neutral rules.
- Original examples of common T-SQL, PL/SQL, Python, BI, and quality patterns.
- Reproducible benchmarks measured inside public labs.
- Architectural decisions and neutral, non-identifying lessons.
- Open-source dependencies with appropriate notices and licenses.

## Never publish without explicit authorization

- Employer/client source code, formulas, configurations, or deployment scripts.
- Production database contents, employee data, GUIDs, account details, or secrets.
- Internal report names, infrastructure addresses, environment screenshots, or logs.
- Client-specific benchmarks, acceptance evidence, documents, or vendor details.
- Any dataset that is merely anonymized but still re-identifiable.

## Project quality gate

A project is featured only when its installation works, tests pass, assets render, links resolve, and all capability/performance claims are supported by the published evidence. Offline tests must not be described as full integration tests.
